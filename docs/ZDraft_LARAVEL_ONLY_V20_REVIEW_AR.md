# مراجعة وتنظيف Z draft — Laravel Only V20

**تاريخ المراجعة:** 3 أغسطس 2026  
**حالة النسخة:** Laravel-only Staging Candidate  
**الباك إند التشغيلي:** `backend/` — Laravel + PostgreSQL  

## النتيجة التنفيذية

تمت إعادة مراجعة نسخة V19، وحُذف باك إند Express/Node القديم من حزمة التشغيل نهائيًا. أصبح داخل المشروع باك إند واحد فقط باسم `backend/` وهو Laravel. واجهة العميل ولوحة التحكم بقيتا Next.js/TypeScript وتستخدمان Laravel عبر `/api/v1`.

لم يتم حذف ملفات `backend/database/legacy-sql` لأنها ليست باك إند Node؛ هي تاريخ Schema PostgreSQL وتستخدمها Migrations Laravel للحفاظ على نفس قاعدة البيانات والعقود والمدفوعات والملفات.

## ما تم حذفه وتنظيفه

- حذف مجلد Express القديم وكل ملفات TypeScript الخاصة بالباك إند السابق.
- حذف Workspace وأوامر وتبعيات Node الخاصة بالباك إند.
- حذف خدمة Queue قديمة غير مستخدمة، والإبقاء على Laravel Scheduler المسؤول عن البريد وPDF والقفل والتنظيف والنسخ الاحتياطي.
- حذف تقارير وتسليمات قديمة استُبدلت بالتنفيذ الحالي حتى لا تربك المطور.
- حذف `package-lock.json` القديم بعد إثبات أنه ناقص تبعيات انتقالية ولا يسمح بـ`npm ci` قابل للتكرار.
- إعادة تسمية عقد توافق المسارات إلى `legacy_api_contract_v18.json`؛ وهو قائمة اختبار فقط، وليس كود Express.

## أخطاء حقيقية اكتُشفت وأُصلحت أثناء المراجعة

1. كانت بعض إعدادات الواجهة ترجع إلى منفذ Node القديم `5000` عند نقص متغير البيئة؛ أصبحت جميع القيم الافتراضية تشير إلى Laravel على `8000`.
2. كانت صفحة جلسات الحساب تتوقع `{items: []}` بينما Laravel يعيد المصفوفة مباشرة؛ تم توحيد الشكل.
3. تم استكمال حقول الملف الشخصي التي تعتمد عليها الواجهة، مثل `emailVerifiedAt` و`createdAt`.
4. تم توحيد شكل تفاصيل العقد الذي تستهلكه الواجهة واختباره.
5. كانت قيم JSONB لبعض أحداث الطلبات والإشعارات وسجل التدقيق قد تصل كنص JSON؛ أصبحت تُفك إلى Objects/Arrays قبل الإرسال.
6. كانت صفحة إشعارات الداشبورد قد تستمر في التحميل عند عدم وجود إشعارات؛ أضيفت حالة تحميل صريحة وحالة فارغة صحيحة.
7. كانت صفحة ملخص الداشبورد متاحة لأي حساب مسجل؛ أصبحت تتطلب `dashboard.view`، والعميل العادي يُرفض صراحة.
8. تم تطبيق CORS وهيدرات الحماية على ردود النجاح والخطأ والـPreflight، حتى لا تظهر أخطاء Laravel في المتصفح كـNetwork Error مبهم.
9. تم اكتشاف خطأ فعلي في استعلام تقارير الداشبورد: عدد Bindings التاريخ كان 24 مقابل 22 Placeholder؛ تم إصلاحه.
10. أضيف فحص دائم لمطابقة SQL Bindings، واختبار PostgreSQL فعلي للسوبر أدمن يفتح الملخص والتقارير وتصدير العملاء.

## ما لم يمكن تشغيله هنا

تمت محاولة الوصول إلى Composer، لكن بيئة التنفيذ لا تحتوي عليه ولا تستطيع الوصول إلى `getcomposer.org`. كما لا تتوفر إضافات `pdo_pgsql` و`imagick` و`mbstring` ولا PostgreSQL. لذلك لم يتم ادعاء نجاح:

- `composer install` أو `php artisan test` Runtime.
- تطبيق Migrations على PostgreSQL حقيقي.
- اختبار Imagick الفعلي من داخل PHP.
- Build كامل للـFrontend والداشبورد؛ لأن سجل npm والحزم غير متاح، والـLock القديم كان غير صالح وحُذف.

## خطوات Staging الإلزامية

```bash
# Backend
cd backend
cp .env.example .env
composer install
php artisan key:generate
php artisan migrate --seed
php artisan test
RUN_DATABASE_TESTS=true php artisan test --filter DatabaseWorkflowSmokeTest
RUN_DATABASE_TESTS=true php artisan test --filter AttachmentImagePipelineSmokeTest
php artisan config:cache
php artisan route:cache

# Frontend + Dashboard، من جذر المشروع
npm install
npm run build
```

بعد `composer install` و`npm install` يجب مراجعة وتثبيت `backend/composer.lock` و`package-lock.json` في المستودع، ثم استخدام `composer install --no-dev --classmap-authoritative` و`npm ci` في النشرات التالية.
