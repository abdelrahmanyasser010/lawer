# Z draft Project Tasks — Laravel Only

## الحالة الحالية

- واجهة العميل: Next.js + TypeScript.
- لوحة التحكم: Next.js + TypeScript.
- الباك إند الوحيد: Laravel + PostgreSQL داخل `backend/`.
- تم حذف باك إند Express/Node من حزمة التشغيل.
- عقد الـAPI الحالي مثبت في `backend/tests/Fixtures/api_contract_v29.json` ويغطي 121 مسارًا، مع الاحتفاظ بعقد التوافق القديم داخل `backend/tests/Fixtures/legacy_api_contract_v18.json` لأغراض الاختبار فقط.
- الواجهة والداشبورد يستخدمان `/api/v1`، والإعدادات الافتراضية تشير إلى Laravel على المنفذ `8000`.
- Demo Mode وFallback المحلي مغلقان افتراضيًا في أمثلة إعدادات الإنتاج.
- وضع التشغيل الحالي يعتمد Super Admin واحدًا، مع بقاء الفريق والإسناد ومحرر القوالب خلف Feature Flags مغلقة.

## مكتمل برمجيًا

- التسجيل والدخول والجلسات وOTP واستعادة كلمة المرور.
- العملاء والملفات الشخصية والإشعارات والبريد.
- العقود والمسودات والإصدارات والمشاركة والقفل والإصدار.
- طلبات إعداد العقود بواسطة محامٍ ومراجعة العقود والمواعيد والملفات الناتجة.
- المدفوعات وإيصالات الدفع والاعتماد والرفض.
- التخزين الخاص وفحص الملفات ومعالجة الصور وThumbnail.
- توليد PDF والملاحق عبر WeasyPrint.
- التقارير والإعدادات وسجل التدقيق.
- Workers/Scheduler للقفل التلقائي والبريد والمستندات والتنظيف والنسخ الاحتياطي.
- Seed مستقل لقوالب البيع والإيجار والفريلانس من ملفات JSON داخل Laravel.

## تحقق ساكن مكتمل

- تطابق 121 مسارًا في عقد الـAPI الحالي مع مسارات Laravel.
- استخراج استدعاءات API من الواجهة والداشبورد ومطابقتها مع Laravel.
- تثبيت عقود شكل الاستجابة للجلسات والملف الشخصي والعقود وJSONB وحالة الإشعارات الفارغة.
- فحص PHP Syntax ومراجع Controllers والكلاسات المحلية.
- فحص TypeScript/TSX Syntax.
- اختبارات محرك القوالب.
- فحص تعريفات القوالب وعدد المواد القانونية.
- فحص عدم وجود أسرار أو ملف `.env` حقيقي داخل الحزمة.

## مطلوب على Staging قبل Production

1. تثبيت PHP 8.4 وComposer والامتدادات المطلوبة.
2. إنشاء `composer.lock` موثق ثم تنفيذ `composer install`.
3. تشغيل PostgreSQL واستخدام قاعدة اختبار منفصلة.
4. تنفيذ `php artisan migrate --seed`.
5. تشغيل `php artisan test` ثم اختبار `DatabaseWorkflowSmokeTest` على قاعدة معزولة.
6. تشغيل `npm ci` وBuild كامل للواجهة والداشبورد.
7. اختبار دورة التسجيل وOTP والعقد والدفع والمشاركة وPDF والتنزيل فعليًا من المتصفح.
8. ضبط Gmail App Password والدومينات وSSL وCookies.
9. تشغيل Scheduler والخدمات الخلفية وتجربة Backup ثم Restore.
10. إصلاح أي أخطاء تكامل تظهر قبل توجيه العملاء إلى النظام.
